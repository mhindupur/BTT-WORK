# BTT Fleet — AWS EC2 Operations Runbook

**Document type:** Installation + troubleshooting runbook  
**App:** BTT Fleet & Fuel (`fleet-web` + `fleet-api` + MySQL `btt_fleet`)  
**Branch:** `cursor/btt-fleet-proposal`  
**Repo:** https://github.com/mhindupur/BTT-WORK  
**Last updated:** 2026-08-07  

This runbook consolidates the full EC2 install procedure **and** real issues faced during first production install (MySQL access denied, empty users table, Nginx 504).

---

## 1. Architecture

```
Browser  →  http(s)://EC2_PUBLIC_IP_OR_DOMAIN
                │
            Nginx (:80 / :443)
           /        |         \
     static FE    /api/*    /uploads/*
  fleet-web/dist    │            │
                    └─ fleet-api (:4000, PM2)
                              │
                         MySQL (:3306)
                         DB: btt_fleet
                         User: btt@localhost
```

| Layer | Path | Runtime |
|-------|------|---------|
| Frontend | `fleet-web/` | Vite build → Nginx static |
| Backend | `fleet-api/` | Node.js Express on PM2 |
| Database | `fleet-db/` | MySQL 8 |

**Do not expose** ports `3306` or `4000` publicly. Only `22`, `80`, and optionally `443`.

## 4. MySQL — create database and app user

### 4.1 Important (Ubuntu)

On Ubuntu, MySQL `root` usually uses **socket auth**. Prefer:

```bash
sudo mysql
```

Not `mysql -u root -p` (that often fails unless you set a root password).

### 4.2 Create DB + user (proven working pattern)

```sql
CREATE DATABASE IF NOT EXISTS btt_fleet CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

DROP USER IF EXISTS 'btt'@'localhost';
CREATE USER 'btt'@'localhost' IDENTIFIED WITH mysql_native_password BY 'BttFleet2026';
GRANT ALL PRIVILEGES ON btt_fleet.* TO 'btt'@'localhost';
FLUSH PRIVILEGES;
EXIT;
```

> Use a password **without `@`**. `@` breaks naive `DATABASE_URL` parsing unless URL-encoded as `%40`.

### 4.3 Verify MySQL login

```bash
mysql -u btt -pBttFleet2026 -e "SELECT USER(), CURRENT_USER();"
```

### 4.4 Issue faced: `ERROR 1045 Access denied for user 'btt'@'localhost'`

**Cause:** User never created, wrong password, or password mismatch with what you type.

**Fix:** Re-run section 4.2 (`DROP USER` + `CREATE USER`), then retest 4.3.

## 7. Backend (fleet-api)

### 7.1 Configure `.env`

```bash
cd ~/BTT-WORK/fleet-api
cp .env.example .env
nano .env
```

Minimum production values:

```env
PORT=4000
DATABASE_URL=mysql://btt:BttFleet2026@127.0.0.1:3306/btt_fleet
JWT_SECRET=REPLACE_WITH_LONG_RANDOM_SECRET

PUBLIC_WEB_ORIGIN=http://YOUR_EC2_PUBLIC_IP
PAYMENT_PUBLIC_BASE_URL=http://YOUR_EC2_PUBLIC_IP
UPLOAD_DIR=/home/ubuntu/BTT-WORK/fleet-api/uploads
WHATSAPP_PROVIDER=stub

ADMIN_EMAIL=admin@btt.fleet
ADMIN_PASSWORD=Admin@123
DEMO_SM_EMAIL=supervisor@btt.fleet
DEMO_SM_PASSWORD=Supervisor@123
```

Replace `YOUR_EC2_PUBLIC_IP` with the real IP (example: `http://15.207.55.223`).

### 7.2 Install, seed users, start with PM2

```bash
mkdir -p ~/BTT-WORK/fleet-api/uploads
cd ~/BTT-WORK/fleet-api
npm install --omit=dev
npm run seed
pm2 start src/index.js --name btt-fleet-api
pm2 save
pm2 startup
# run the sudo command printed by pm2 startup
```

Seed should print:
```text
[seed] Admin login: admin@btt.fleet / Admin@123
[seed] Supervisor / Site manager login: supervisor@btt.fleet / Supervisor@123
```

### 7.3 Verify API locally

```bash
pm2 status
curl --max-time 5 http://127.0.0.1:4000/api/health
# {"status":"ok","app":"btt-fleet-api"}
```

### 7.4 Issue faced: `users` table empty / cannot login

**Symptom:**
```sql
SELECT * FROM users;
-- Empty set
```

**Cause:** Schema loaded, but **`npm run seed` was never run** (or ran against a different DB/password).

**Fix A — seed:**
```bash
cd ~/BTT-WORK/fleet-api
grep DATABASE_URL .env
npm run seed
mysql -u btt -pBttFleet2026 btt_fleet -e "SELECT id,email,role FROM users;"
pm2 restart btt-fleet-api
```

**Fix B — manual admin insert (if seed unavailable):**
```sql

  'BTT Administrator',
  NULL,

);

-- Optional site manager:
```

## 9. Nginx reverse proxy

```bash
sudo nano /etc/nginx/sites-available/btt-fleet
```

```nginx
server {
    listen 80;
    server_name _;

    client_max_body_size 20M;

    root /home/ubuntu/BTT-WORK/fleet-web/dist;
    index index.html;

    location /api/ {
        proxy_pass http://127.0.0.1:4000;
        proxy_http_version 1.1;
        proxy_connect_timeout 10s;
        proxy_read_timeout 60s;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /uploads/ {
        proxy_pass http://127.0.0.1:4000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

Enable:
```bash
sudo ln -sf /etc/nginx/sites-available/btt-fleet /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl reload nginx
```

If app lives under `/opt/btt/BTT-WORK`, change `root` accordingly.

## 11. Issues faced during first EC2 install (and fixes)

### Issue A — MySQL `ERROR 1045 (28000): Access denied for user 'btt'@'localhost'`

| Item | Detail |
|------|--------|
| When | `mysql -u btt -p btt_fleet < fleet-db/schema.sql` |
| Cause | `btt` user missing or wrong password |
| Fix | Recreate user with `sudo mysql` + `DROP USER` / `CREATE USER` (section 4.2) |
| Prevention | Always test `mysql -u btt -p... -e "SELECT 1;"` before schema load |

### Issue B — Nginx `504 Gateway Time-out` on `/api/auth/login`

| Item | Detail |
|------|--------|
| When | Browser login via `http://EC2_IP/api/auth/login` |
| Observed | FE reachable; API health OK (`pm2 online`, `/api/health` 200) |
| Root cause found | `users` table empty — no admin to authenticate / incomplete setup |
| Secondary causes | API down, MySQL hang, wrong Nginx `proxy_pass` |
| Fix | Ensure users exist (`npm run seed` or manual INSERT), restart PM2, retest login on `:4000` then via Nginx |

**Decision tree used:**
1. `pm2 status` + `curl 127.0.0.1:4000/api/health` → API healthy  
2. Direct login to `:4000` → fails / empty users  
3. `SELECT * FROM users` → Empty set  
4. Seed / manual INSERT → login works  

### Issue C — `SELECT * FROM users` returns Empty set

| Item | Detail |
|------|--------|
| Cause | Schema applied; seed not run |
| Fix | `cd fleet-api && npm run seed` **or** manual INSERT (section 7.4) |
| Verify | `SELECT id,email,role FROM users;` returns admin (+ SM) |

### Issue D — Cloud `127.0.0.1:5174` vs laptop localhost (dev note)

Cloud agent localhost is **not** your Mac. For EC2 production use public IP via Nginx. For local Mac use `./scripts/local-up.sh`.
